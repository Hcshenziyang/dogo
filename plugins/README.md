# DogO DSH 插件

两个独立插件，运行在官方 DSH 内；DogO 不再包装一套桌面 Agent。

| 插件 | 当前功能 |
| --- | --- |
| `dogo-memos` | 在线列表/项目筛选、编辑、删除、创建时附带指令；原生 AI 查询、读取、创建/更新/追加工具 |
| `dogo-devices` | 本机接单开关与执行目录、设备在线状态/禁用；经 DogO 服务查看、新建、续聊、停止目标电脑会话 |

两者可分别安装，共用一个登录/续期实例。只有设备插件建立执行 WebSocket；仅作为访问方的电脑无需启用本机接单。正文和项目存于 DogO，完整会话保存在执行电脑 DSH。

## 构建与安装

需要 Node 22+、pnpm 9；代理回归测试另需 `openssl` 生成临时测试证书。最初验收使用官方 DSH `0.2.0-rc.2`，后续修复已在 DSH `0.2.1-rc.3` 验证。在 `plugins/` 执行：

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm run pack
```

产物为 `release/dogo-memos-0.2.6.tgz`、`release/dogo-devices-0.2.6.tgz`，不提交源码仓库。使用 DSH 自带插件管理器安装到指定 profile：

```sh
dsh plugin --profile web add /绝对路径/dogo-memos-0.2.6.tgz /绝对路径/dogo-devices-0.2.6.tgz
```

同版本重打包调试时使用新的安装包路径或升级版本，并核对已安装 bundle；DSH 包管理器可能沿用旧文件缓存。

安装或更新后重启此 profile（桌面端退出并重新打开 DSH），不能仅刷新页面：后台模块可能仍使用旧版本。侧栏全局面板出现两个入口。账户由服务端管理员创建；任意入口登录同一个 DogO 服务。在右上角“DogO 设置”中开启本机访问，开关直接保存；首次默认执行目录为本机用户目录，也可改为其他已有的绝对目录。显示“本机可被访问”后，访问方登录同一账户并选择这台在线设备。公网地址必须是 HTTPS；HTTP 仅允许回环地址。反向代理需支持设备 WebSocket。

macOS 插件后台支持系统设置中的 HTTPS 代理及常见例外；也可使用进程的 `HTTPS_PROXY` / `NO_PROXY`。当前不支持 PAC 自动代理和带账户密码的代理 URL；此时需要配置不带认证的 HTTP(S) 代理。

测试时务必给两台 DSH 使用**不同的独立 `DSH_HOME`**，避免接触个人 profile。一个 `DSH_HOME` 只允许运行一个 DogO 插件宿主；进程锁防止同时消费同一设备身份。卸载使用 `dsh plugin --profile web remove dogo-memos dogo-devices` 后重启；卸载不删除个人备忘录及 DSH 会话。停止接单不会停止已被 DSH 接收的执行。

## 界面与交互

- 两个插件使用 DSH 正式 `sidebar.panellist` 和 `main` 插槽，直接在主面板打开；不修改 DSH DOM，不再使用覆盖整个界面的业务弹窗。
- 备忘录采用全宽方格，首行搜索/新建/刷新/设置，第二行按项目筛选及排序；点击卡片打开右侧编辑抽屉，窄窗口抽屉占满宽度。没有侧栏和重复页头，置顶按用户要求暂不实现。支持已加载记录搜索及基础 Markdown 阅读预览；项目/原有分类/标签按需展开，创建时可附带指令，普通编辑不会重新投递。
- 方格里的分类沿用现有 `project` 项目字段，不新增分类模型，不把原有 `category` 字段改名或迁移。项目 chips 来自已加载的服务器项目；草稿尚未提交的项目不新增筛选项。搜索包含已加载备忘录的本机草稿；排序仅作用于已加载结果，不表示全量服务器排序。
- 卡片显示本机未同步草稿和真实接收状态；新建草稿也可从卡片继续。关闭抽屉不提交/丢弃草稿，再打开恢复；重新进入页面先显示方格并保留上次选择。`Escape` 关闭抽屉，`Tab` 保持在抽屉内，关闭后恢复焦点；在网格的非输入控件上按 `/` 聚焦搜索，搜索内 `Escape` 清空。编辑时 `⌘/Ctrl+S` 或 `⌘/Ctrl+Enter` 保存。本机存储失败时保留当前页面内存草稿并明确报错，刷新/退出前仍需复制内容。
- 每条备忘录和新建内容分别保留本机草稿，保留上次选择。手动保存或 `⌘/Ctrl+S` 才提交服务。版本冲突显示原写入与服务器内容；清除待确认记录不修改服务器，重新读取服务器内容需要明确确认。
- 设备页按远端 DSH 工作区显示和筛选项目；新建会话可选已有项目，执行目录与项目成员关系由远端 DSH 处理。未分组会话仍使用设备默认目录；备忘录的项目文本不会自动映射为工作区。
- 会话可选择执行电脑提供的模型及其支持的思考强度，显示当前原生模型选择。沿用 DSH 的选择语义：更新该会话下一次请求，并同步远端默认模型；不转发 API Key 或修改模型提供商配置。
- 设备页显示设备、会话和对话；正文按角色展示，工具参数折叠，原生执行错误直接显示。保留上次设备/会话选择及未发消息，发送采用 `⌘/Ctrl+Enter`；未知接收结果继续使用原请求重试。
- 账户与本机执行配置集中在右上角设置抽屉，设备标题旁不重复放置齿轮。访问开关直接保存，执行目录单独保存；连接中、可访问和连接异常分别显示，关闭访问不依赖目录仍然存在。支持 DSH 深浅主题、键盘焦点和窄窗口分栏切换。

## 可靠性边界

- JWT/刷新凭据使用 DSH 原生 credential record `dogo/session`；密码不保存、不传给浏览器配置。服务地址和账户不同则设备身份不同，切换前退出。
- `DSH_HOME/dogo/` 保存设备 ID、执行配置、待确认写入、投递到原生会话的映射；文件权限 0600、原子替换。不要随意删除该目录、复制到另一台运行中的电脑，或提交其中的数据。
- 先保存投递映射，再以稳定 sessionId/requestId 创建和发消息，DSH 确认后才记录并 ACK。ACK 丢失重投返回原会话；当前验证依赖 rc.2 原生创建和 prompt 的幂等语义。
- `accepted` 表示 DSH 接收，不代表工具、模型或任务完成。访问方关闭页面不取消执行；执行电脑退出、休眠或等待本地审批仍会影响进度。
- AI 工具 `dogo_write_memo` 的说明要求模型仅按明确指令调用；技术层强制参数、版本和待确认写入保护，不额外增加逐次人工审批。整条更新必须提供完整字段及原版本；追加带原版本；不向 AI 开放删除。未知写入保留原 payload，不自动更新版本重放。清除待确认记录前人工核对服务器；此动作不撤销已经成功的写入。
- 本地编辑草稿保存在浏览器存储，按服务和账户隔离。它不是完整离线同步；当前不生成独立冲突副本、不自动合并。
- 在线调用使用 HTTPS/WSS 和账户认证，**没有上游的端到端加密**，服务端可见转发内容。服务端不写入会话副本，但备忘录、指令及关联会话 ID 正常持久保存。
- 远程界面显示最近 30 条消息对应的原生记录，每 2.5 秒读取一次；不替换 DSH 主界面。审批、用户提问、附件及复杂工具界面留在执行电脑。项目字段不自动变成本地目录。

## 代码来源

会话 carrier 和浏览器控制路由复用 `ds-harness-remote v0.5.18` 的必要部分，来源、改动与 MIT 许可证见 [vendor/dsh-remote/ORIGIN.md](vendor/dsh-remote/ORIGIN.md)。未整体 fork 上游运行时；账户、队列、Android 仍使用 DogO 实现。两个分发包携带对应第三方许可证。

## 验证

`tests/` 验证桥接参数/Peer、未知原生接收结果后的稳定 ID、持久重投、认证续期和备忘录版本保护。后端独立运行 `uv run pytest -q`。

集成脚本需要自行启动隔离 FastAPI 和官方 DSH，合成账户写入权限 0600 的 `$EVAL_CACHE/account.json`，字段为 `username/password`。服务器使用 18184，执行 DSH 使用 18185；不得指向个人实例。

- `EVAL_CACHE=... node scripts/remote-options-smoke.mjs`：在 18185 的隔离 DSH 验证项目归属/目录、创建重试、模型及思考强度实际执行、错误项目/模型拒绝。缓存中需有 `host.log`、合成 `account.json` 和 `project-one` / `project-two` 目录。
- `EVAL_CACHE=... EVAL_DSH_LOG=... node scripts/smoke.mjs`：已安装插件共享登录、离线投递/上线执行、续聊去重和冲突保留；检查 DSH 控制路由拒绝未认证/不可信来源。
- 重启同一隔离 DSH 后追加 `--after-restart`，验证身份和会话恢复。
- 在隔离 profile 载入 `tests/fixtures/model.mjs`、将默认模型设为 `dogo-eval/fixture`，追加 `--tools` 验证原生工具循环实际读写备忘录。此 fixture 使用本机 macOS 安装路径；**只能用于测试**，不会调用商业模型。
- 访问方另用独立 `DSH_HOME` 在 18186 运行，`EVAL_VIEWER_LOG=... node scripts/ui-smoke.mjs` 验证 UI 登录/写备忘录及 A 经服务器操作 B。需提供 Playwright，可通过 `EVAL_PLAYWRIGHT_PACKAGE` 指向已有安装，通过 `EVAL_BROWSER_PATH` 指定独立自动化浏览器可执行文件；脚本不使用个人浏览器 profile。

插件依赖本仓库当前 FastAPI `/api` 认证、备忘录、待确认写入与投递协议，不能把旧版 DogO 服务当作兼容后端；此 UI 改动不升级或部署服务端。

当前验证与限制见 [插件变更说明](CHANGELOG.md) 和仓库 [STATUS.md](../STATUS.md)。Android 远程会话界面、真实模型/复杂工具及物理多设备网络仍待验证。
