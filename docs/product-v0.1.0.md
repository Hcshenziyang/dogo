# DogO 产品文档 v0.1.0

日期：2026-10-18\
版本性质：产品需求基线，不是应用发行版本。\
适用对象：DogO 手机端、Mac 客户端、配套服务器及 DSH 桥接插件。

DogO 是同一用户跨设备使用的个人助理客户端。用户可以从手机继续 Mac 上的 DSH 原会话，向桌面资料箱投递记录，并在各端共享一个个人记忆文件夹。工作仍由原设备执行，手机不迁移或复制执行会话。

本文以本轮用户确认的产品行为为准，替代此前“每次到 Mac 确认”“仅支持 DogO 新建会话”“资料发送即执行”等旧假设。产品要求与实现状态分开；现状见本文第 13 节和 [STATUS.md](../STATUS.md)。

## 1 产品定位与范围

### 1.1 目标

- 无人值守：手机明确发送的执行指令，在已授权且在线的 Mac 上自动运行，不等待 Mac 本机点击。
- 连续工作：手机和 Mac 是同一 DSH 会话的多个操作入口，后续消息继续进入原会话。
- 随手记录：资料只进入 DogO 自己的资料箱，供用户稍后判断处理，不触发 Agent。
- 共享记忆：全局个人记忆采用专用文件夹，各授权端可以读写并同步。
- 应用在线：DogO 启动并登录后才参与远程收发；关闭窗口可以驻留后台，不另设脱离 DogO 的独立守护服务。

### 1.2 平台边界

| 平台 | 产品职责 | 边界 |
| --- | --- | --- |
| 手机 | 轻量对话、项目选择、任务续聊、资料投递、结果阅读、远程确认、记忆读写 | 不迁移桌面会话，不以持续后台运行 Agent 保证任务可靠性 |
| Mac | 运行 DogO、接入 DSH、执行本机任务、展示资料、同步个人记忆 | 远程上线依赖 DogO 应用及有效账号登录 |
| 网页 | 复用任务、会话、资料及设置交互，通过授权服务连接设备 | 浏览器不直接取得本机文件或命令权限；实际接入需单独验证 |
| Windows | 保留协议和平台适配位置 | 当前暂不推进平台实现与验收 |
| 服务器 | 身份与设备、可靠投递、结果保存、会话内容同步、附件与个人记忆同步 | 不默认运行自主 Agent，不代替设备进行模型推理 |

手机轻量 Agent 可以接 DeepSeek 等用户配置的模型 API，调用已授权的远程 MCP 工具及适用的 Skill。复杂本机工作委派给桌面；收发、刷新和同步本身不依赖模型。

2026-10-19 用户明确选择手机独立：采用成熟轻量运行库与原生模型 API 配置，不将手机对话转交 Mac，也不声称 Android 内运行 DSH。手机本地对话在前台运行；后台可靠任务仍通过持久中转交给桌面。模型密钥不参与个人记忆同步。

### 1.3 非目标

不做多人协作 SaaS、长期主题空间、完整项目管理或 IDE、开放插件市场、多引擎热切换、跨设备执行会话迁移、项目源码全量同步，也不在 DogO 内重新设计项目并发调度。

Mac 屏幕观察、点击、输入、编码委派和 SSH 保留为已确认的能力方向，通过 DSH 及兼容插件接入并分别验收，不因底层已安装某个插件就认定能力可用。

## 2 产品对象

| 对象 | 定义 | 关键关系 |
| --- | --- | --- |
| 账号 | 个人数据与设备授权的归属 | 一个账号可绑定多台设备 |
| 设备 | 已登记的手机、Mac 或其他执行端 | 展示名称不是身份；以稳定标识路由 |
| DSH 实例 | 显式接入 DogO 的 DSH 运行环境 | 归属原设备，不扫描未接入实例 |
| 项目 | 本机已登记的文件夹 | 关联设备和本地目录，不扩展为主题空间 |
| 任务会话 | 一段可持续的工作过程 | 绑定设备、DSH 实例和原生会话标识 |
| 执行轮次 | 一条指令引发的一次执行 | 成功或失败不妨碍任务会话继续 |
| 消息 | 会话中的用户输入、答复、补充或状态 | 有稳定标识，支持关联和去重 |
| 资料记录 | 待用户处理的文字、文件、图片等 | 存入 DogO 资料箱，可关联项目 |
| 个人记忆文件 | 全局个人记忆目录内的文件 | 与资料记录、项目记忆及会话历史分开 |

任务会话与执行轮次不能混用：某一轮完成后，手机仍可以在同一任务下发送下一条指令。一次停止不应删除会话。

不同设备上的同名目录不自动视为可互换的执行位置；手机选择设备上的项目，不能靠目录名称猜测执行目标。

## 3 DogO 运行生命周期

| 状态 | 远程行为 |
| --- | --- |
| DogO 已启动、已登录、连接正常 | 收件、同步，并按本机策略自动执行 |
| 窗口关闭但 DogO 驻留托盘 | 保持在线，不因关窗口停止任务 |
| DogO 未启动、已注销或完全退出 | 设备离线；服务器保存待投递内容 |
| Mac 断网、休眠或关机 | 显示离线或连接未知；不假定任务完成，也不自动交给另一设备重跑 |
| DSH 暂不可用 | 设备连接状态与执行器状态分开，任务等待或明确报错 |

支持开机登录系统后启动 DogO，并恢复 DogO 账号登录；这不是修改操作系统的自动登录设置。用户可以关闭自启动或主动注销。

完全退出时应明确提示进行中的任务及影响，不承诺退出后仍能远程控制。DogO 自己管理的执行进程与独立启动的 DSH 生命周期分别处理，但独立 DSH 存活不能代替 DogO 上线。

重新上线后补收资料和未开始的指令；对已经开始、结果不明的执行先核对状态，不盲目重跑。

## 4 执行任务与原生会话

### 4.1 发送与自动执行

用户选择设备、必要时选择项目，输入指令并明确发送。服务器先持久保存，再通知执行端。执行端验证身份和本机策略后自动开始，不增加逐任务的 Mac 本机确认步骤。

手机离线时先保存本地待发记录；服务器尚未确认接收时不得显示“已送达”。设备离线时显示“已保存，等待设备上线”，不显示“执行中”。

附件应在服务端可用后再允许依赖它的轮次开始；缺少附件不能被静默忽略。

### 4.2 原会话续聊

- 手机能查看已接入 DSH 实例中通过 DSH 原生界面创建的会话，不仅限于 DogO 新建任务。
- 打开会话后，后续输入仍由原设备、原实例和原 DSH 会话处理。
- 同一条指令重复投递不得重复启动执行；同步索引不能重复创建会话。
- 原会话丢失、不可访问或恢复失败时明确提示，不能静默换新会话或换设备。
- 手机与 Mac 的输入、答复和状态应汇入同一会话记录。
- 会话正在运行时，遵循 DSH 支持的追加、排队或停止后续聊行为，并在界面明确呈现；不另造项目并发调度。

### 4.3 历史与结果

服务器保存已同步的会话正文、执行状态和结果，手机在 Mac 离线时仍可阅读。界面标识最近同步时间，不把缓存当成实时状态。

详细工具调用和日志按需展开或获取，不要求默认全量传输。附件独立存储并关联会话，不将大文件塞进消息正文或每轮模型上下文。

结果区分完整成功、失败、停止、输出截断、等待输入和连接未知。保留已生成的部分内容；“任务已接收”或模型最后一句话不能作为执行成功的唯一依据。

上下文压缩与原生会话恢复交给 DSH；DogO 不用另开会话掩盖截断，不固定承诺某个上下文长度能稳定运行。

### 4.4 远程确认与停止

超出既定权限或需要用户补充时，确认请求回到手机，包含任务、动作、目标和影响。确认结果必须关联原请求，过期或重复答复不能误作用于另一轮执行。

手机离线或未回复不代表同意。停止请求与停止完成分开显示；在执行端确认前不能显示已停止。

## 5 资料箱

资料投递与执行任务是两条明确入口。资料支持文字、文件、图片等内容，可关联项目，也可作为不关联项目的普通记录。

1. 手机提交资料，服务器保存正文及附件。
2. Mac 离线时，手机显示“已保存，待 Mac 接收”。
3. DogO 上线后补收，记录出现在 DogO 自己的资料箱。
4. 用户稍后查看、标记已处理、整理或明确转成执行任务。

资料不会自动调用 Agent、写入项目源码或现有项目文档，也不会自动成为个人长期记忆。资料箱不是外部笔记软件的默认写入接口。

转成任务时保留原记录及关联，不能因 Agent 执行失败而丢掉资料。记录与任务结果可相互引用，便于“根据刚才那张图继续处理”。

资料的已保存、已投递、已读和已处理应区分；通知消失不意味着记录被删除。

## 6 项目目录

项目由桌面端登记并向同账号授权设备提供基本信息。手机至少能看到项目名称、简介或基本说明、所属设备、可用状态和更新时间。

手机发送的是稳定项目标识，由执行端解析本地目录；绝对路径不作为跨设备身份，也不必默认公开。重名项目应通过设备信息区分。

进入手机应用时自动刷新，也提供手动刷新。Mac 离线时保留最近已同步的列表并标明信息时间；刷新不应伪造实时状态。

项目目录移动、失效、撤销公开或不再允许执行时，应返回明确状态，不猜测替代路径。项目源文件和项目记忆不因项目出现在手机列表中而自动上传。

项目名称、基本信息和执行关联是本版边界；分支协作、问题管理、跨设备仓库同步和项目写入并发不在 DogO 另行实现。

## 7 全局个人记忆

### 7.1 文件夹是记忆载体

全局个人记忆保存在明确选择的专用文件夹中。Mac、手机及获准的服务器端 Agent 可以读取、写入；各端持有自己的文件副本，由同步机制传播变化。

DogO 不要求把记忆转换成另一套用户画像数据库。允许为检索和同步建立索引，但文件仍是可查看、编辑、导出和恢复的记忆载体。

DSH 的项目内或编码会话记忆保持独立，默认不纳入此目录。资料箱、会话正文及同步事件也不是个人记忆文件。

### 7.2 同步行为

- 支持记忆写入后自动同步、进入应用或恢复连接后补同步，以及设置中的手动同步。
- 用户或 Agent 直接修改目录文件也应被同步，不限定只能通过某个工具写入。
- 离线写入先保存在本地，联网后发送；同步状态不能影响本地读取。
- 同步创建、修改、重命名和删除；保留足以恢复的历史或回收记录。
- 只同步明确配置的目录，不扫描个人主目录、凭据目录或其他项目。
- 全量覆盖指定目录不等于每次全量上传，也不等于向每轮模型注入全部记忆。

文件类型、容量、留存期限及版本存储方式由技术设计明确，不将当前原型的限制误写成最终产品上限。

### 7.3 Agent 处理冲突

手机和 Mac 修改同一个文件时，不用最后上传者静默覆盖另一份内容。

1. 保存共同基线和冲突双方；无法取得基线时明确保留双方。
2. 建立独立的记忆维护任务，交给在线、获准且具备相应能力的 Agent。
3. Agent 根据来源和版本分析合并；无法判定的事实矛盾不得随意丢弃一方。
4. 提交合并前再次核对当前版本；处理期间有新修改则重新检查，不能覆盖新内容。
5. 成功后同步结果并保留可回退记录；不能解决时保留冲突，通知用户人工处理。
6. 没有可用 Agent 时先排队；限制自动重试，避免冲突任务无限循环。

默认可优先使用 Mac，其他授权 Agent 作为备选；具体选择是可调整策略，不要求为此在服务器常驻 Agent。冲突处理不能绕过 DogO 未启动或设备未授权的限制，也不应打断用户原有编码会话。

## 8 账号与执行权限

### 8.1 两层权限

服务端负责账号、设备和数据访问权限，判断谁能发送、读取、领取或回复。执行端负责目录、命令、屏幕操作及外部工具权限。

手机明确发送就是执行意图；本机策略已允许的动作自动执行，不再要求人在 Mac 确认。支持用户为无人值守配置可持久生效的广泛或完全访问权限，不把当前只读原型视为产品上限。

完全访问必须是用户在可信配置入口选择的策略，可查看和撤销；不能由消息中的字段自行授予。策略撤销或账号失效后，不因旧任务已排队而继续使用失效授权。

### 8.2 身份和凭据

设备名称只用于显示，发送身份从认证信息取得。设备注册、注销、撤销和凭据失效必须可识别；同账号多设备不能变成任意外部设备接入。

凭据保存在平台安全存储或服务端受保护配置中，不写入 APK、前端源码、会话正文或普通记忆目录。设备撤销应阻止后续访问，但不承诺抹除已经下载到该设备的数据。

传输使用认证和加密连接。服务器保存正文和文件副本不等于已实现端到端加密；具体静态加密、密钥恢复和端到端方案属于待明确的技术安全设计。

服务器端 Agent 如果获准理解记忆，必须被视为有权读取内容的执行端，而不是匿名中转组件。

## 9 页面与交互

### 9.1 手机

保留“收件箱 / 任务 / 设置”的主要导航，不把记忆正文突出为独立主入口。

- 收件箱：资料、提醒和需要用户处理的事项；资料不能误显示成正在执行的任务。
- 任务：设备和项目选择、会话列表、原生 DSH 会话、连续消息、流式结果、停止和待确认动作。
- 设置：账号、设备、连接状态、同步入口、个人记忆目录相关管理、模型和通知设置。
- 刷新：进入应用触发刷新，并提供手动刷新；失败时保留本地内容和最近成功同步时间。
- 通知：任务完成、失败、待输入或待授权、无法自动解决的记忆冲突。后台通知与前台刷新分别验证。

手机轻量对话允许调用配置模型和获准工具；不把发送普通资料自动解释成对话执行。

### 9.2 Mac

提供 DogO 资料箱、设备连接与账号状态、项目登记、任务与会话入口、DSH 配置入口及同步管理。原生 DSH 界面可以继续使用，不要求所有工作从手机或 DogO 新建。

托盘明确显示在线状态，区分关闭窗口、注销和完全退出。首次准备无人值守时，应能检查模型、DSH、插件和系统权限是否可用；缺失能力应在手机可见，而不是只留在本机日志。

## 10 系统职责与技术边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| DogO 客户端 | 账号入口、项目和任务界面、资料箱、设置、原生系统集成 | 第二套 Agent 循环 |
| DogO 本机适配层 | DSH 接入、连接、授权、状态映射、原生凭据与生命周期衔接 | 脱离 DogO 应用的独立常驻产品 |
| 上游 DSH | 模型调用、工具循环、原生会话、上下文压缩和执行状态 | DogO 账号、跨端资料与个人记忆同步 |
| DogO DSH 插件 | 会话发现与操作、事件映射、工具和记忆接口桥接 | 复制或 fork DSH 核心 |
| 服务端 | 身份与设备、持久收发、会话副本、附件、同步及恢复 | 默认自主决策或执行所有任务 |
| 能力插件 | 模型路由、电脑操作、编码工具、SSH 等可替换能力 | 自动取得全部账号数据或绕过授权 |

执行路径：手机或网页 → DogO 服务 → 原设备 DogO → 原 DSH 会话及工具 → 服务端保存结果 → 发起端阅读。

资料路径：手机 → 服务端持久保存 → Mac DogO 资料箱 → 用户自行处理。

记忆路径：任一授权端修改专用目录 → 同步服务传播版本 → 其他端更新；冲突走独立维护任务。

MCP 与普通客户端 API 共用业务和授权逻辑。MCP 可提供设备查询、任务投递与结果查询等工具；通知只负责提示变化，不能替代持久保存、执行去重和断线补读。

Skill 提供工作说明和资源，实际操作仍需要适当的执行宿主。电脑操作、编码委派、SSH 和订阅模型路由分别验收，不能将“订阅插件已安装”当成“已能控制编码应用”。

沿用 TypeScript、React、Electron、Capacitor、Node.js 和上游 DSH 的现有方向。消息、记忆和工具保持逻辑边界，不要求拆成多个微服务；数据库、事件传输及移动推送的具体实现可以替换。

## 11 可靠性与失败处理

- 服务器确认已保存后，消息和资料不能只存在于内存；进程重启后可补读。
- 任务、轮次、消息和执行身份分开，发送重试不增加第二次副作用。不能以网络层“恰好一次”为前提。
- 会话执行真相来自原设备 DSH；服务器保存同步副本，不根据心跳消失擅自判定成功或重跑。
- 手机退出、锁屏或断网不自动取消桌面执行；重连后恢复读取状态和结果。
- 账号无权访问、项目失效、模型不可用、附件缺失、输出截断和执行中断必须给出可理解的错误。
- 自动重试区分安全的传输重试与可能重复副作用的执行重试；后者必须核对执行归属。
- 同步冲突、未保存的草稿和未发出的指令不能在刷新或应用重启后静默消失。
- 平台能力不足、系统权限缺失或登录失效时明确阻塞原因，不用模拟数据代替真实成功。

## 12 产品验收标准

以下为目标验收，不表示已经全部通过。测试优先使用合成目录、测试记录和明确授权的能力。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC01 | 手机创建执行任务 | Mac 无人点击，按既定权限执行，手机收到真实结果 |
| AC02 | 接续 DSH 原生会话 | 手机看到原生创建的会话；追加输入前后设备、实例和会话标识一致 |
| AC03 | 多轮任务 | 一轮完成后能继续发送，历史和上下文保持关联，不另建任务冒充续聊 |
| AC04 | 执行端离线 | 服务器保存待执行指令；DogO 上线后执行一次；重发和重连不重复执行 |
| AC05 | 远程确认与停止 | 超权请求可在手机处理；请求与原动作绑定；停止完成由执行端确认 |
| AC06 | 离线阅读 | Mac 离线后仍能读取已同步正文和结果，并看到同步时间 |
| AC07 | 资料离线投递 | 服务端先保存；Mac 上线后资料箱出现；整个过程不调用 Agent |
| AC08 | 项目刷新 | 手机进入或手动刷新后显示桌面登记项目及新鲜度；无效项目不执行 |
| AC09 | 个人记忆文件同步 | 多端读写、离线补同步及手动同步可用；项目记忆和凭据目录不被扫描 |
| AC10 | Agent 解决记忆冲突 | 冲突双方保留；独立 Agent 产生可追溯合并；提交时不覆盖更新版本 |
| AC11 | 冲突无法解决 | 无 Agent 时排队；无法合并时保留冲突并通知人工，不无限重试 |
| AC12 | 应用生命周期 | DogO 自启登录后上线；关闭窗口保持在线；完全退出后不再接收执行 |
| AC13 | 权限与撤销 | 无效设备、错误账号及撤销授权不能访问或执行；正常预授权任务不重复询问 |
| AC14 | 手机后台通知 | 在支持的目标手机环境中验证完成、失败及待确认通知，不能以网页刷新代替 |
| AC15 | 故障恢复 | 服务端或客户端重启不丢已保存资料和结果；执行状态未知时不盲目重跑 |

Mac 电脑操作需另验屏幕观察、点击和文字输入；编码委派需验真实改动与测试结果；SSH 需验输出、退出码及断线状态。Windows 不用 Mac 测试结果代替验收。

## 14 技术验证与可调整策略

不重新讨论已确认的无人值守、原会话续聊、资料不执行、个人记忆目录和 DogO 应用在线边界。以下项目在实现时落实或通过实验确定：

- DSH 会话发现、历史读取、运行中续聊、取消和审批接口的版本兼容性；不通过复制会话规避接口不足。
- 已接入实例的历史同步规模、工具日志及附件按需读取、删除和留存策略。
- 账号登录方案、凭据撤销、存储加密、备份和恢复；端到端加密不作为已经实现的能力。
- 手机后台通知的可达范围和平台限制；不可用时仍需保留持久收件和前台补读。
- 冲突处理 Agent 的选择、模型、重试次数，以及无可用执行端时的排队策略。
- 同一会话运行中追加消息的具体呈现，以及完整退出时进行中任务的明确提示。
- 记忆文件类型和容量限制、项目元信息发布范围、资料箱删除与回收策略。
- 电脑操作插件的兼容性和系统授权，编码与 SSH 的实际可用性。

默认优先原设备、原会话；默认资料不执行；默认同步不覆盖冲突；默认失败不伪装成功。没有用户进一步要求，不扩展为服务器常驻 Agent、跨设备会话迁移或完整项目管理。
