# 0002：持久任务信箱与显式共享记忆目录

日期：2026-10-16。状态：用户要求先做服务器服务；以下为已实现的首个原型边界。

## 决策

- 先在 `apps/others/services` 实现确定性服务，不等待客户端或在服务器安装 Agent。
- 任务信箱为可配置逻辑路径，每条路径指定设备；手机任务的结果仍归原任务，按发起端身份通知。
- SQLite 事务同时保存任务和事件；在线 SSE、离线游标重放。MCP 负责工具调用，不代替通知连接。
- 领取绑定 executionId，不因心跳过期自动重领，避免重复执行有副作用的编码任务。
- 同步只覆盖明确选择的共享记忆文件夹，项目本地记忆保留本地；项目概要仅在主动放入共享目录后同步。
- 共享文件使用版本检查、删除标记与本地基线；冲突显式报告，不最后写入者静默覆盖。
- 任务与记忆是独立模块，可同进程或不同配置/数据库分开部署；当前只支持每库一个服务进程。

## 权衡与未完成

SSE 不能唤醒关机/休眠设备；手机 OS 推送与 Agent 自启动另行设计。重放保证事件可补读，不保证副作用恰好一次。
执行失联需要原执行端核对，原型不自动接管。终态结果可离线回读，但还没有审批/取消/附件协议。
共享目录降低实现复杂度，也要求用户明确目录和敏感数据边界；暂不支持二进制、中文文件名及端到端加密。
同步服务保存文本版本，不是服务器目录镜像；用户可通过同步客户端物化到指定目录。
具体 API、配置、运行方法和限制见 [服务说明](../../apps/others/services/README.md)。
