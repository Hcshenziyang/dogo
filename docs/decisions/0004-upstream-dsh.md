# 0004：上游 DSH + DogO 客户端/薄插件

日期：2026-10-18。状态：用户确认，后端切换已实施；扩展能力分项验收。

## 决策

不复制、fork 或重写 DSH 核心。DogO 负责客户端、设备任务、授权入口与配置；Agent 循环、会话和工具扩展交给固定版本的官方 DSH。

本次采用官方 Web 后端而非 SDK 简化通道，保留 DSH 原生会话、插件设置及审批界面。`packages/dsh-plugin` 调用 DSH 原生服务，`apps/runtime` 管理生命周期和现有中转协议。

## 迁移边界

- 保留 Android APK、服务器协议、设备配对、SQLite 任务记录和本地模型。
- 移除 Pi Coding Agent 执行模块/直接依赖；旧会话保留查看，不自动格式转换或续聊。
- 独立 DSH home/profile，旧 `~/.dsh`、`~/.codex` 登录凭据不复制。
- 仅回环监听，桥接凭据不进渲染层；原生 Web 登录地址只由 Electron 主进程打开。
- 已有 DogO 任务仍只读；切换执行引擎不自动授予命令、写文件或 GUI 权限。
- 关闭窗口可后台执行；完全退出或父进程断开会关闭 DSH。

## 插件及后续

`dsh-codex` 是独立订阅登录/模型路由，不是 Codex Desktop 自动化。`dsh-native-memory` 是工作目录范围记忆，不满足个人全局同步。
GUI 插件的版本兼容和系统权限、个人记忆同步、SSH、独立 DSH 插件直接接中转仍需逐项实现验证；不因插件已安装就标记这些能力完成。

每次升级验证本机工具往返、拒绝路径、取消、失败/截断、重启续聊和压缩。模拟测试与实际模型、手机端到端、Windows 验收分别记录。
