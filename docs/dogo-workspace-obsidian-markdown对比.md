# dogo-workspace 与 Obsidian：Markdown 编辑、阅读体验对比

> 本文记录 0.1.7 时的对比与建议。0.1.8 已加入阅读视图、格式快捷键、双链、图片和表格编辑，实际范围与验证结果见 `STATUS.md` 和 `plugins/README.md`。

对比时间：2026-11-14。DogO 依据本地 `1f066a8` 的 `dogo-workspace` 0.1.7 源码和项目测试记录；Obsidian 依据官方帮助文档，主要比较内置功能。本文是源码与文档对照，不是两款应用的同机逐项实测；外观、快捷键细节与边缘语法的实际表现仍需用样例验证。差距等级是针对使用场景的定性判断，不是完成度百分比或已批准的开发需求。

## 结论

**简单文字、标题和待办：可用，差距中等；把现有 Obsidian 笔记原样拿来阅读或编辑：差距大。** DogO 已有本地 Markdown 文件、实时预览、源码编辑、复选框和自动保存；但它目前更像轻量笔记编辑器。Obsidian 有独立阅读视图、较完整的 Markdown 渲染与表格交互，还围绕库内链接、附件和属性形成完整使用流程。

最直接影响日常使用的五项：本地图片无法预览；双链不能像 Obsidian 一样导航；表格只能回到 Markdown 源码编辑且单元格格式不渲染；没有独立阅读视图；公式、图表、提示块等 Obsidian 内容不能按原样呈现。文件仍是 Markdown 并不等于在两边能得到相同的显示或操作结果。

## 逐项对比

| 场景 | DogO 当前行为 | Obsidian 内置体验 | 差距及实际影响 |
|---|---|---|---|
| 编辑与阅读模式 | 一个可编辑的 CodeMirror 编辑器，可切换「实时预览 / 源码」；没有独立只读阅读视图。 | 编辑视图含实时预览和源码模式，另有阅读视图，可并排查看。 | **大**：DogO 阅读时仍处于编辑器，点击/选择可能进入编辑；不能用独立阅读视图完整排版。 |
| 标题与基本强调 | ATX 标题 `#` 至 `######`、加粗、斜体、删除线、行内代码有预览样式；当前行显示语法。 | 基本格式在实时预览和阅读视图中呈现。 | **小到中**：简单笔记接近，但实际边界语法及视觉细节未逐项实测。 |
| 列表和任务 | 无序列表符号可装饰；`- [ ]` / `- [x]` 可点击切换，另有跨笔记待办汇总。依赖 CodeMirror Markdown 键位处理列表输入。 | 支持格式化列表与可交互任务项。 | **中**：常用清单可用；嵌套、缩进和快捷操作尚未逐项对照，不能推断完全一致。 |
| 普通链接 | `[文字](https://...)` 在非活动行隐藏标记并呈链接样式；代码没有实现链接打开处理。 | 可在笔记中使用外部链接与内部链接。 | **大**：外观像链接不等于可点击跳转；具体宿主快捷操作未实测。 |
| 库内双链与反向链接 | 未见 `[[笔记]]` 的解析、补全、跳转、重命名联动或反向链接实现。 | 支持 Wikilink、Markdown 内链、标题和块链接及链接补全；可在重命名时更新链接。 | **大**：已有双链知识库会失去重要的导航关系，源文本可编辑但不能当作等价知识库使用。 |
| 图片与附件 | 非活动行仅把标准 Markdown 的 HTTP(S) 图片显示成图片；点击图片回到对应源码。相对路径、本地图片及 `![[图片.png]]` 未实现预览。 | 支持库内图片及外部图片嵌入，并支持其他文件如 PDF 的嵌入。 | **大**：以截图为主的笔记难以直接阅读；远程图片还依赖网络。 |
| 表格 | 非活动表格生成 HTML 表格预览；点击「编辑表格」回到源码。单元格使用纯文本，内嵌强调和链接等不会按格式渲染。 | 实时预览可直接编辑表格；支持插入、增删、移动和排序行列。 | **大**：简单表格能看；复杂单元格显示及日常修改成本明显更高。 |
| 代码块 | 编辑器保留原文；源码中未见专门的代码块渲染组件或语言高亮配置。 | 阅读视图支持代码块和语言高亮。 | **中到大**：代码笔记可编辑，但围栏、排版及高亮不能假设等价；具体外观待实测。 |
| 公式、Mermaid、提示块 | 未见 MathJax、Mermaid 或 Obsidian callout 专门解析与渲染。源码仍可查看和编辑。 | 支持数学公式、Mermaid 图表和 callout 提示块。 | **大**：含公式、流程图或 `> [!note]` 的笔记无法按 Obsidian 效果阅读。 |
| YAML 属性与标签 | YAML 是正文文本，没有 Obsidian 式属性表单、类型管理或属性查询界面。 | frontmatter 可显示为结构化属性，并支持类型与搜索。 | **大**：依靠属性组织的笔记仍保留原文，但缺少表单化操作。 |
| 搜索和文件组织 | 当前列表按标题过滤；知识目录为平铺结构，不支持嵌套目录。 | 支持库内目录、全文搜索及属性搜索。 | **大**：笔记多时难以按正文定位；已有多层目录不能直接按原结构浏览。 |
| 保存与外部修改 | 编辑约 750ms 后触发保存，失焦也触发；文件版本变化时拒绝覆盖并保留编辑区草稿。纯 CRLF 保留，混合行尾可能统一为 LF。 | 本地文件编辑与保存；具体冲突和同步行为取决于使用方式。 | **中**：DogO 有明确的覆盖保护，但不是跨进程锁；两边同时修改仍需人工处理。 |
| AI 辅助 | 同页独立 Harness 会话可读取知识文件、提交修改建议；应用前预览，文件版本变更时拒绝覆盖。 | 此处只比较 Obsidian 内置 Markdown 功能，不把第三方 AI 插件算作默认能力。 | **DogO 有不同的工作流**：优势是 AI 对话与受控建议直接在工作区内；不代表 Markdown 渲染更完整。 |

Obsidian 的视图与语法依据：[视图与编辑模式](https://obsidian.md/help/edit-and-read)、[基本语法](https://obsidian.md/help/syntax)、[高级语法和表格](https://obsidian.md/help/advanced-syntax)、[内部链接](https://obsidian.md/help/links)、[嵌入文件](https://obsidian.md/help/embeds)、[属性](https://obsidian.md/help/properties)、[Callouts](https://obsidian.md/help/Editing%2Band%2Bformatting/Callouts)。

## 用几个具体例子理解

1. **日记和清单**：`# 今天`、普通段落、`**重点**` 和 `- [ ] 买牛奶`，DogO 已能编辑、预览并勾选；如果主要这样使用，差距相对可控。
2. **截图笔记**：`![[截图.png]]` 或 `![截图](附件/截图.png)` 在 Obsidian 可作为本地图片嵌入；DogO 当前不会把它们显示为图片。HTTP(S) 标准图片可以显示，但不能替代离线附件。
3. **关联笔记**：`[[项目计划#进度]]` 在 Obsidian 可链接到另一篇的标题；DogO 缺少对应解析与导航，阅读时看到的关联不能按同样方式使用。
4. **项目表格**：DogO 可看到普通表格，但要新增一行需编辑 `|` 分隔的源码，单元格中的 `**重点**` 也显示为原始文本；Obsidian 可在表格内直接操作行列和格式。
5. **技术文档**：包含公式、Mermaid、callout、代码高亮的文档，在 Obsidian 阅读视图能呈现相应效果；DogO 目前主要保留源码，阅读负担明显增加。

## 范围与待验证

- 上述 DogO 的“不支持”指当前源码中没有对应功能，不能据此断言所有语法都损坏或保存后丢失。不要直接在唯一一份重要笔记上验证复杂语法。
- 没有实际导入个人 Obsidian 库，也没有修改个人笔记；未做两款应用同屏、长文性能、复制粘贴、输入法和无障碍专项测试。
- 建议后续用一份**合成样例**逐项验证：嵌套列表、外链点击、代码块、表格对齐及单元格格式、双链、本地图片、frontmatter、公式与 callout；记录显示、编辑、保存后的原文及重开结果。
- DogO 源码依据：`plugins/workspace/markdown-editor.ts`、`client.ts`、`store.ts`、`styles.ts` 和 `plugins/README.md`。项目历史验证见 `STATUS.md`。

## 优化建议与验收例子

以桌面端「写一篇笔记，回读，再沿引用打开资料」为目标，建议分三批。先复用现有 CodeMirror 编辑器和 Markdown 文件存储。下面的顺序是产品建议，具体工作量和手感仍需样例验证。

| 顺序 | 用户动作与期望 | 建议改动与验收 |
|---|---|---|
| 第一批 · 连续编辑 | 在同一行修改一个词时，旁边的链接和强调保持稳定。选中文字按 Cmd+B 可以加粗，再按可取消。 | 调整 markdown-editor.ts 按整行显露标记的逻辑，对行内格式按光标或选区命中的语法节点处理。加粗、斜体操作走 CodeMirror 事务。用「同一行两个加粗词加一个链接」检验光标移动、中文输入法组词、撤销和重做。 |
| 第一批 · 阅读与外链 | 按 Cmd+E 回读，复制正文、打开网页，再返回原段继续写。 | 在 client.ts 增加编辑与阅读切换，保留原有源码开关。阅读视图从当前草稿渲染标题、引用、列表、代码块和普通表格。阅读时单击打开网页，编辑时用修饰键打开。验收时在自动保存前切换，核对最新一句可见、返回时光标和滚动位置恢复，阅读操作不触发正文写入。 |
| 第二批 · 笔记内链 | 输入两个左方括号后选择另一篇笔记，阅读时点进去，再退回原段。 | 先用现有平铺文件列表补全，以文件 ID 定位，显示标题可不同。复用 openDocument 的保存流程。覆盖同名显示标题、目标不存在、未保存草稿和返回定位，再扩展到标题锚点、反向链接与重命名更新。 |
| 第二批 · 本地配图 | 粘贴一张截图，断网重开仍能看到，已有相对路径图片也能显示。 | store.ts 现有文件接口面向笔记和画布。新增限定知识目录的图片读取与附件写入，编辑器插入相对路径，阅读与实时预览共用解析。用同名截图、中文空格文件名、缺失图片及指向库外的符号链接验收，确认不会覆盖附件或读取库外文件。 |
| 第三批 · 表格操作 | 在单元格内改一个值，按 Tab 到下一格，右键插一行。 | 当前 MarkdownTable 用纯文本填单元格。先复用行内渲染显示强调和链接，再做单元格编辑与行列操作，保持源码为标准管道表格。用含转义竖线、行内格式和对齐标记的表格验收，修改一格再撤销，核对其他格和对齐信息。 |
| 按笔记类型补充 | 长文中从大纲跳到小节，技术笔记中直接读公式或流程图，资料库中按正文找回笔记。 | 长文先做基于标题的大纲，技术文档按使用频率补代码高亮、callout、数学或 Mermaid。全文搜索和子目录适合单独评估，因为会影响文件索引、链接解析和 AI 读取范围。 |

如果主要用途是日记和清单，第一批即可单独验收。如果主要用途是阅读已有 Obsidian 笔记，应优先连同内链和本地图片一起验收。如果主要维护项目表格，可将单元格编辑提前。以上排序依据日常操作受阻的程度，尚未用个人笔记统计功能使用频率。
